# Takt — UI studies, round 2

18 варіантів для вибору: по три для головної, календаря, списку предметів, предмета, екзамену та прогресу.

Відкрий `/home/kpyr/Projects/Takt/design-explorations/2026-09-22-v2/index.html`. Усі шрифти локальні. Кнопки «Обрати» зберігають комбінацію в браузері; її можна скопіювати й надіслати в чат. Прокручування всередині кожного телефону показує нижню частину макета.

Коди: **Г1–Г3**, **К1–К3**, **С1–С3**, **П1–П3**, **Е1–Е3**, **Р1–Р3**. Рекомендована комбінація: **Г1 · К1 · С1 · П2 · Е1 · Р2**.

Композицію, палітру та навігацію можна обирати окремо: наприклад, Г2 у синій темі та з центральною кнопкою +. Третя колонка демонструє темне оформлення, але не вимагає темної теми для цієї композиції.

## Що виправляємо порівняно з Android Pulse

- Забагато рівнозначних великих карток → одна основна, решта як легкі рядки або групи.
- Забагато вертикального місця в шапках → компактний заголовок і метадані.
- Перемикачі статусу/типу оцінювання займають огляд → перенести до меню предмета.
- Дата й кнопка редагування екзамену займають пів екрана → короткий квиток або один рядок.
- Результат, прогноз і допуск конкурують між собою → чітко різні блоки та підписи.
- Великий відлік/статистика без наступної дії → видима конкретна робота, пара або крок.

## Межі

Це статичні UI-концепції для вибору. Інтерактивні лише галерея, збереження вибору та прокручування. Кнопки всередині телефонів, календарні режими і повзунок Е2 показують запропоновані стани; вони не реалізують функції Android.

Усі навчальні дані демонстраційні, а не перевірений особистий навчальний план. 81/180 — показник загальної цілі; сам по собі він не доводить виконання вимог диплома або всіх предметних блоків. 24/30 + до 70 на екзамені = досяжні 94/100. Для A за демонстраційною шкалою треба 92 загалом, тобто 68/70 на екзамені. Завершення безбального завдання змінює допуск, а не бали.

Е2 пропонує новий калькулятор сценарію; С3 — нове групування за діями. Це продуктові пропозиції, які потребують окремої реалізації після вибору. Скорочені назви у компактних календарних/плиткових видах мають відкривати повну назву в деталях. Під час перенесення слід зберегти реальні модулі, редагування, теми, ручні оцінки, всі п’ять вкладок, 48dp зони натискання і масштабування шрифту.

Цього раунду Kotlin/Gradle/Room не змінювались. PNG у `previews/` — рендери HTML, а не скриншоти нового APK.

## Перевірка

- Галерея завантажена у прихованій вкладці Codex IAB; усі шість блоків і 18 варіантів присутні в DOM.
- PNG експортовані окремим headless Chromium за допомогою Playwright: дошка 1320 CSS px, масштаб 1.5, вихідні PNG 1980×1752. Окремі вікна перегляду не запускались.
- Кожен PNG переглянуто через `view_image`: композиція, текст, типографіка, кольори, відступи, календарна геометрія, розділення балів/допуску/прогнозу.
- Виправлено зіткнення 10:00 із лінією 10:05, контраст темної контурної кнопки, винесено дату Е3 у видимий підзаголовок і прибрано службові пояснення з макетів предметів.
- Немає горизонтального переповнення екранів у дошках; на ширині браузера 390px ширина документа теж 390px. Вміст телефонів навмисно прокручується вертикально.
- Вибір Г1 та К1 оновлює підсумок; зберігається після перезавантаження. JavaScript синтаксично коректний, помилок сторінки в Chromium немає.
- Це перевірка концепцій, не Android/TalkBack-аудит і не твердження про готову production-реалізацію.
